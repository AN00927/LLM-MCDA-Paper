## 2. The experiment, and why it is built the way it is

A_H makes one extraction LLM call per scenario returning hidden engineering
parameters (r_value, seer, gpm, ...), which a deterministic physics calculator
then uses to score the three alternatives. A_H is the **only** architecture whose
prompt shows all three alternatives as a numbered sequence, which is the format
the position-bias literature concerns. A_D and A_E score one alternative per
stateless call, so reversal there only permutes a two-element "other options"
list.

**The manipulation:** reverse `alternative_1/2/3` values in the extraction prompt
and nothing else. Verified to change exactly 2 prompt lines (alt_1 and alt_3;
alt_2 is the fixed midpoint of a 3-reversal) and never a non-alternative line.

**Scoring is always in canonical alternative order, in every arm.** This is
load-bearing. `sentinel_utils.apply_mavt_ranking` uses a stable sort, so exact
score ties resolve by input row order. Scoring both arms in the same order means
that tie-break cannot manufacture a difference. Do not "fix" this by passing
reversed alternatives to the calculator.

**Three arms exist per model:**

| Arm | Runs | What it is |
|---|---|---|
| shipped | 5 | the benchmark runs, collected 2026-07-29 |
| control | 3 | shipped order, re-sent 2026-08-03, identical code path |
| reversed | 5 | reversed order, 2026-08-03 |

The **control arm exists because the shipped runs record no timestamps**. A gap
between reversed and shipped is equally consistent with an ordering effect and
with provider drift. Control-vs-shipped measures drift directly;
reversed-vs-control holds session fixed.

**Primary test: exact label-permutation over runs** (`_exchangeability_test`).
Under the null, a reversed run is just another run, so relabel which runs carry
the reversed label across all assignments and ask how often the observed
within-minus-between separation is matched. Reported on three bases:

- `control` — same session, cleanest, fewest relabelings
- `shipped` — cross-session, confounded with drift
- `pooled` — shipped + control as one shipped-order group. **Primary.** Pooling
  is grouping by condition (both are shipped order; session is a nuisance
  factor), not a data-dependent choice, and it inflates the reference group's
  internal spread, which shrinks the statistic. Conservative direction.

**Do not use McNemar as the headline.** It is in the workbook for completeness
and it is structurally underpowered here: A_H's shipped runs disagree on top-1
for only 5-15 of 195 scenarios, and an exact binomial on 5 discordant pairs
cannot reach p < 0.05 at any split. A McNemar null here is an artefact of the
test, not evidence about ordering. This was caught by an audit subagent and is
the single most important methodological correction of the session.

## 3. Results as of 3 reversed runs (pooled basis, 165 relabelings)

| Model | choice sep | p | param sep | p | Holm (8 tests) |
|---|---|---|---|---|---|
| qwen | -0.0038 | 0.806 | **+0.0508** | 0.0061 | **0.0488** |
| gptoss | -0.0030 | 0.649 | -0.0055 | 0.679 | 1.00 |
| deepseek | -0.0087 | 0.988 | -0.0491 | 0.842 | 1.00 |
| gemini | -0.0005 | 0.758 | **+0.0485** | 0.0061 | **0.0488** |

**0/4 models show decision-level order sensitivity. 2/4 show parameter-level
order sensitivity**, both surviving Holm across all eight tests.

Both significant p-values sit **exactly at the permutation floor** (1/165 =
0.0061), meaning the observed labelling was the most extreme of all 165. The
test is saturated: the true p could be far lower and cannot be measured at this
resolution. That is the only reason runs 04-05 were added — floor drops to
1/1287 = 0.00078, Holm to about 0.006.

**A low p means "distinguishable", NOT "one ordering is better."** Accuracy
answers that separately and says neither wins:

| Model | control tau | reversed tau |
|---|---|---|
| gemini | 0.9293 | 0.9271 |
| qwen | 0.8895 | **0.8963** |

Signs disagree across models, gaps under 0.007. Reversal shifts **which**
parameter values come out, not **how good** they are.

**Drift check passed.** control-vs-shipped parameter identity vs within-shipped
baseline: gemini 0.8441/0.8497, gptoss 0.3684/0.3800. No session drift, so the
pooled basis is sound.

**Incidental finding worth a line in the paper.** DeepSeek's within-group
parameter agreement was 0.4230 (shipped, 5 days earlier), 0.6393 (control,
today), 0.6632 (reversed, today). Both of today's arms show it equally, so it is
a **session effect, not an arm effect**. Without the contemporaneous control this
would have been readable as a finding about reversal.
